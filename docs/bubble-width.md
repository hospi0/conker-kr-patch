# 말풍선 폭 규칙 — 번역 예산의 근거

**2026-08-02 확정.** 실기 스테이트 3종(원본 / PoC / 한글)의 구조체 실측값을 오차 0 으로 재현한다.
검증 = `python tools/bubble.py`.

---

## 0. 왜 이 문서가 필요한가

첫 한글 빌드에서 **한글 문장은 원본보다 좁은데(120 → 98) 말풍선은 오히려 커져서**
왼쪽이 화면 밖으로 잘리고 텍스트가 왼쪽 끝에 붙었다.

화면 실측:

| | 말풍선 | 텍스트 | 좌여백 | 우여백 |
|---|---|---|---|---|
| 원본 | x 98..923 (825 px) | 205..741 (536) | 107 | 182 |
| 한글 | x 91..1036 (945, 좌측 잘림) | 119..555 (436) | **28** | **481** |

원인은 렌더러 버그가 아니다. **말풍선은 화면에 뜬 그 문장이 아니라, 그 메시지에 속한
자막 전체의 최대 폭으로 정해진다.** 우리는 첫 문장만 번역했고, 남은 영문 자막이
자모 글리프(advance 13)로 측정되어 최대폭이 154 → 239 로 뛰었다.

## 1. 말풍선 폭

```
말풍선폭(자막 구조체 +0x38) = 1.15 * Wmax + 10.35
Wmax = 그 메시지에 속한 모든 자막의 최대 줄 폭
```

| 빌드 / 메시지 | 자막별 폭 | Wmax | 예측 | **실측 +0x38** |
|---|---|---|---|---|
| 원본 | 120 154 147 108 66 | 154 | 187.45 | **187.45** |
| PoC (글리프 3개만 자모) | 121 164 138 105 63 | 164 | 198.95 | **198.95** |
| 한글 (전량 자모, 1문장만 번역) | 98 237 239 167 112 | 239 | 285.20 | **285.20** |
| 원본, `0xBD` 형 메시지 | 55 54 94 43 75 | 94 | 118.45 | **118.45** |
| 한글, 메시지 통째 번역 | 118 90 95 72 102 | 118 | 146.05 | **146.05** |

마지막 행이 이 문서의 결론을 실기로 확인한다. 자막 5개를 전부 번역하자 말풍선이 정상으로
돌아왔다 — 화면 실측 폭 654 px (원본 825 px 를 `146.05/187.45` 로 환산한 643 px 과 1.7% 오차),
**자막 5개를 넘기는 동안 폭이 655/653/655/653/654 로 불변**, 텍스트는 좌우 여백을 두고 말풍선 안에 들어간다.

세 점이 정확히 선형이다. 최대폭을 첫 2개 자막으로만 잡으면 기울기가 1.181 로 어긋나고,
6개(다음 `0xBF` 문자열 포함)로 잡으면 원본이 254.15 가 되어 어긋난다.
**→ 메시지 경계와 「최대폭」 규칙이 동시에 확정된다.**

텍스트 원점(`RAM 0x80032AAC`)도 같은 Wmax 를 쓴다: `x = C - Wmax/2`, C ≈ 105.
한글 빌드는 `105 - 239/2 = -14.5` (화면 밖) → 왼쪽 여백 8 로 클램프되어 왼쪽에 붙었다.
현재 자막의 폭/2 는 구조체 `+0x30` 에 따로 저장된다(원본 60.0 / 한글 49.0 = 120/2, 98/2).

## 2. 줄 폭 계산식

측정 함수 `RDRAM 0x802D08D4` — `Measure(a0=문자열, a1=&폭, a2=&높이, a3=&?)`.

```
advance = (w+1) + xoff - 1 = w + xoff        메타 = [w+1][h+1][xoff][yoff]
0x20  공백    pen += 4,  줄높이 최소 12       (룩업이 0x60 센티널을 돌려준다)
0x0A  줄바꿈  최대폭 갱신, pen = 0            ★원시 바이트로 판정한다
0xBC          다음 1바이트와 함께 건너뜀 (폭 0)
0xA1~0xA7     폭 0
0xA8~0xFF     디스패처(VA 0x850415E0) 반환폭을 pen 에 더함 — 버튼 아이콘 등
0x00          측정 종료
줄 폭 = max(줄별 pen)
```

`xoff` 는 우리 렌더러 패치(`lbu`→`lb`) 덕분에 부호 있는 값이다. 그래서 조합형의
중성·종성(xoff = -12)은 advance 0 으로 정확히 겹치고, **줄 폭에도 0 으로 들어간다.**
널 글리프(w=1, xoff=-1)도 advance 0 이라 패딩이 폭을 늘리지 않는다 — 실측 확인.

## 3. 메시지 경계

```
0xBF                       메시지 시작
  문자열 <00> 문자열 <00> …   ← 이 메시지의 자막 목록 (연속된 0x00 은 건너뛴다)
0xBF                       다음 메시지
```

- 자막 개수 = 메시지 구조체 `+8` (`CountSubtitles`, VA `0x8516a770`)
- 자막 추출 = `RDRAM 0x80380878` (VA `0x8516c878`) — **`0x00` 으로만 나눈다**
- 최대폭 갱신 루프 = `RDRAM 0x8037F920`
- 현재 자막 배치 = `RDRAM 0x8037FBF4` (`측정폭 >> 1` → 구조체 `+0x30`)

### `0xBD` 도 자막 분리자다 — 단, 치환을 거쳐서 (실기 확인)

대사 상당수가 `hi, berri !⟨BD⟩hello. . .⟨BD⟩…` 형식이다. 추출 함수는 `0x00` 만 보는데도
이게 제대로 나뉘는 이유는, **메시지가 활성화될 때 게임이 버퍼의 `0xBD` 를 제자리에서 `0x00` 으로
치환**하기 때문이다. 같은 메시지가 대기 중일 땐 `berri !\xbdhello`, 표시 중일 땐 `berri !\x00hello`.
현재 페이지는 정적 스크래치 버퍼(`0x800315E8` 등)로 `0x00` 종단 복사된다.

실기 확인 — "hi, berri !" 말풍선:

| 가설 | Wmax | `+0x38` 예측 | 실측 |
|---|---|---|---|
| `0xBD` 가 줄을 안 끊고 누적 | 212 | 254.15 | |
| **`0xBD` 가 페이지를 끊음** | **94** | **118.45** | **118.45** ✅ |

페이지별 폭은 `[55, 54, 94, 43, 75]`. 그리고 **말풍선은 페이지가 바뀌어도 크기가 그대로다** —
"HI, BERRI !"(55) 와 "HELLO. . ."(54) 화면의 말풍선이 둘 다 정확히 528 px 였다.
`+0x38` 로 환산한 예측 521 px 과 1.3% 오차.

→ `tools/bubble.py` 의 `split_message` 는 `0x00` 과 `0xBD` 를 모두 분리자로 취급한다.

## 4. 번역 제약

> **한 메시지(`0xBF` 블록)에 속한 모든 자막의 모든 줄이, 그 메시지 원문의 최대 줄 폭 이하일 것.**

- 줄 단위가 아니라 **메시지 단위** 예산이다.
- **한 자막이라도 미번역으로 남기면 그 메시지 전체가 깨진다.** 글리프 95칸을 전부
  자모로 덮었기 때문에 남은 영문은 자모 글리프로 측정된다(문자당 advance 13).
  부분 번역 상태의 말풍선 깨짐은 버그가 아니라 필연적 증상이다.
- 검사 = `tools/bubble.py` 의 `check(원문자막들, 번역자막들, ...)`.

```python
import bubble
m = bubble.Metrics.from_rom()          # 또는 from_rdram('work/...bin')
subs = bubble.split_message(buf)
wmax, bub, each = bubble.message_budget(subs, m)
```

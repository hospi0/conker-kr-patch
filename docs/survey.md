# ROM 조사

대상: **Conker's Bad Fur Day (USA)**, 64MB(512Mbit), CIC-6105, cart `NF`, region `E`, rev 0
식별 해시는 `config/rom.json` 에 있고 모든 도구가 읽기 전에 검증한다.

## ROM 맵

| 범위 | 크기 | 내용 | 상태 |
|---|---|---|---|
| `0x001000`–`0x029000` | 160KB | 상주 엔진 MIPS 코드 (비압축) | 확정 |
| `0x029000`–`0x040000` | 92KB | 데이터 + RSP 마이크로코드 (F3DEX fifo 2.08) | 추정 경계 |
| `0x040000`–`0x1331000` | 19MB | **rzip 애셋 뱅크** | 확정 |
| `0x1331000`–`0x29AF000` | 19.5MB | **MP3 뱅크** | 추정 경계 |
| `0x29AF000`–`0x3F8C000` | 22MB | VADPCM 오디오 | 추정 경계 |
| `0x3F82000`–`0x3F8B000` | 36KB | 비압축 애셋 (5개국어 튜토리얼 텍스트 평문) | 추정 경계 |
| `0x3F8C000`–끝 | 464KB | `0xFF` 패딩 | 확정 |

부트 세그먼트는 **RAM = ROM + 0x80000000** 으로 그대로 매핑된다
(ROM `0x2000` == RAM `0x80002000` 로 검증).

## 압축: rzip

```
[BE32 원본크기][raw deflate 스트림]
```

gzip 에서 헤더·트레일러만 뗀 것이다. **매직 바이트가 없다.**

> ⚠️ 초기 조사에서 `1f8b`/`1172`/`78xx` 시그니처 스캔이 0건이라 deflate 를 배제했는데,
> 그건 오판이었다. rzip 은 애초에 시그니처에 걸릴 수가 없다.
> 올바른 탐지법은 **BE32 가 그럴듯한 크기인 위치마다 raw inflate 를 시도**하는 것이다.

블록에는 정렬 제약이 없다. 상당수가 앞 블록 바로 뒤에 붙지만 전부는 아니다
(표본에서 연속쌍 45/97). 위치는 애셋 테이블이 정한다.

> ⚠️ 4바이트 정렬을 가정하고 스캔하면 블록 하나를 놓칠 때 그 뒤가 통째로 갭이 된다.
> 그래서 처음에 커버리지가 36.7% 에 그쳤다. `tools/blocks.py` 는 1바이트씩 훑되
> 블록을 찾으면 그 크기만큼 건너뛴다.

추출 결과 (`python tools/blocks.py`):

```
10,427 블록   압축 14.47MB  →  원본 27.23MB   (스캔 범위의 76.4%)
```

## 애셋 인덱스 테이블

`ROM 0xBB1BA0`.

```
[BE32 offset][BE32 size] × N      offset 은 테이블 시작 기준
off[k] + size[k] == off[k+1]      빈틈없이 연속
마지막 엔트리는 size 에 bit31
```

첫 offset(`0x5D8`) = 테이블 자기 크기(187×8) → **[테이블][데이터] 자기완결 컨테이너**이고,
각 엔트리가 다시 같은 형식이라 **재귀 구조**다. 루트 187엔트리 → 146노드 → 리프 5,320개 / 3.82MB.

> ⚠️ 「오름차순 BE32 런」 스캔으로는 못 찾는다. offset 과 size 가 번갈아 나와
> 단조증가 수열이 아니기 때문이다. 압축 해제 데이터 안에도 같은 형식 컨테이너가 365개 더 있다.

## 오디오

음성·음악은 **MP3** 다 — `FF F3 30 C0` 프레임이 78바이트 간격으로 289,631개.
MPEG-2 Layer III, 모노, 24 kbps, 22.05 kHz. Rare 가 RSP 용 MP3 디코더를 넣었다.
효과음은 VADPCM(9바이트 프레임).

`0x29AF000` 이후 22MB 에서 rzip 블록은 41개(0.1%)뿐 — 전부 오디오가 맞다.

## 텍스트

- 인코딩 **ISO-8859-1**
- 제어코드: `0x0A` 줄바꿈 / `0xBA` 종료 / `0xBD` 자막 구분 / `0xBF` 블록 시작
- 대사는 rzip 블록 약 364개, ROM `0x188328`–`0x132E528` (특히 `0x1180000`–`0x1210000` 밀집)
- **모집단 확정 (2026-08-02, `tools/corpus.py`)**
  **자막 3,205개 / 고유 2,928개 / 74,893바이트, 말풍선(메시지) 973개, 299블록.**
  2단계로 뽑는다: ①어절 구조로 영어 문장인 런을 씨앗으로 잡고(2,234개, 사전 불필요)
  ②씨앗에서 텍스트 영역으로 번져 짧은 UI 문자열·고유명사까지 채택(+971개).
  실기로 확인된 두 메시지(자막 5개/Wmax 154, 자막 5개/Wmax 94)를 정확히 재현한다.
  (이전 「사전 매칭 2,454개」는 하한값이었다.)
- **말풍선 경계 = 자막 사이 간격이 정확히 1바이트면 같은 메시지, 2바이트 이상이면 새 메시지.**
  코퍼스 전체에서 간격 1 이 2,232곳, 2~8 이 약 750곳으로 분포가 두 갈래로 갈린다.
- ⚠️**텍스트 밀도로 대사 블록을 가리려 하면 안 된다.** 4비트 텍스처가 ASCII 범위라
  밀도 1.00 으로 잡힌다(`DDDUDEDDES4...`). 공백·어절 구조가 진짜 판별자다.
- ⚠️**`0xBF` 는 보편적인 메시지 마커가 아니다** — 코퍼스 전체에서 12곳뿐이다.
- `0x188328` 블록(189KB raw)은 시스템·UI 문자열
